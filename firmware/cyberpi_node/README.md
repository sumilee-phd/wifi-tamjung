# 사이버파이 측정 노드

10/31 강연의 측정 노드는 사이버파이(CyberPi) 4대, 본체 스티커 05~08이다. ESP32 펌웨어(`../wifi_tamjung_node`)는 쓰지 않는다.

## 파일

| 파일 | 역할 |
|---|---|
| `cyberpi_node.py` | 노드 코드 틀. 핫스팟 이름·암호·노드 번호 자리가 비어 있다 |
| `make_nodes.py` | 저장소 밖 `hotspot.txt`를 읽어 기기별 완성본 4개를 `노드코드/`에 쓴다 |

완성본에는 핫스팟 암호가 들어가므로 저장소에 올리지 않는다.

## 올리는 순서

1. `C:/sumiWork/2026/1031_10월의하늘/hotspot.txt`에 `SSID=`, `PASS=` 두 줄(도서관 와이파이 세기도 재려면 `LIB=이름` 한 줄 추가).
2. `python firmware/cyberpi_node/make_nodes.py` → `노드코드/cyberpi_node_05.py` ~ `_08.py`.
3. mBlock 5(5.6) 실행 → 장치 탭에서 사이버파이 추가 → USB로 연결 → **업로드 모드** → 오른쪽 위 Python 편집기 → 완성본 내용을 통째로 붙여 넣고 **업로드**.
4. 기기 화면에 `노드 05  강단`, `-xx dBm ####`, `전송 n회`가 올라가면 끝. 강연 앱 측정 탭의 탐정 노드 표에 05가 뜬다.
5. 기기마다 번호에 맞는 파일로 3~4를 반복한다.

## 기기 조작

- A: 이전 구역, B: 다음 구역 (강단 → 왼쪽 벽 → 가운데 → 오른쪽 벽 → 비상구 쪽)
- 조이스틱 클릭: 전송 멈춤·재개 (자리를 옮길 때)
- LED: 초록 3~4칸, 노랑 2칸, 빨강 1칸 이하·전송 실패·접속 끊김
- 호일로 감싸면 전송이 끊기고 서버 화면에 3초 뒤 신호 끊김으로 표시된다.

## 노트북 쪽 준비

- 모바일 핫스팟을 2.4GHz로 켠다. 사이버파이는 5GHz에 붙지 못한다.
- 노트북의 상위 연결(인터넷 공유 원본)도 2.4GHz여야 한다. 노트북이 5GHz 와이파이에 붙어 있으면 설정이 2.4GHz여도 핫스팟이 5GHz로만 뜬다(G14 MediaTek MT7922에서 10/29 실측). 휴대폰 핫스팟 2.4GHz나 USB 테더링을 상위로 쓴다.
- 핫스팟 절전(장치가 없으면 자동 끄기)은 끈다.
- 방화벽에 UDP 8601 인바운드 허용(관리자 PowerShell 한 번): `New-NetFirewallRule -DisplayName "WifiTamjung UDP 8601" -Direction Inbound -Protocol UDP -LocalPort 8601 -Action Allow`
- `.\run.ps1`로 서버를 띄운다. 노드는 핫스팟 게이트웨이(보통 192.168.137.1)를 서버로 자동 인식한다.

## 검증 기록

- 2026-08-26 실습실: 사이버파이 → 와이파이 → 노트북 서버 UDP 8601 전 구간 실측(KIPEE 노드 코드). TCP와 urequests는 실패, UDP만 쓴다.
- 2026-10-29: 사이버파이 05 실기기 전 구간 확인. mBlock 5.6 업로드 → 핫스팟 SUMI(2.4GHz, WPA2) 접속 → UDP 8601 1초 전송 → 서버 `/api/state`에 -32dBm, 끊김 없음. 방화벽 규칙 없이도 수신됨. 처음 실패 원인은 노트북 상위 연결이 5GHz였던 것(위 준비 항목).
