## 1. 목적과 배경

초등학생 중심 청중 약 40명이 눈에 보이지 않는 와이파이 전파를 직접 예측하고 측정해, 강연장 한 방의 "전파지도"를 함께 완성하는 참여형 강연을 운영한다. 이를 위해 두 가지를 만든다.

1. **강연 앱**: 강연자 노트북에서 돌아가며 프로젝터로 보여 주는 앱. 측정 노드가 보낸 신호세기를 받아 실시간 지도를 그린다.
2. **공개 사이트**: 강연 전후에 아이와 부모가 들어오는 정적 웹사이트. 강연 소개, 전파 놀이터, 집에서 하는 탐정 미션, 완성된 도서관 전파지도를 담는다.

강연자 혼자 준비, 설치, 진행, 철수를 할 수 있어야 하므로 **운영 가이드 영상**을 함께 만든다.

작년(2025) 서산 대산도서관 강연 「소리의 과학」(들리는 파동)에 이어 올해는 전파(보이지 않는 파동)를 다루는 연작 2편이다. 작년 강연 사이트(oct-sky2025.vercel.app)와 같은 방식으로 공개 사이트를 배포한다.

### 4.1 ICT와 우리나라 전파 이야기

기존 단계 안에 녹여 넣고 새 단계를 만들지 않는다. 추가 분량은 약 3분이며 48분 전체 길이는 그대로 둔다. 학교 소개는 홍보가 아니라 진로 이야기로 한다.

| 단계 | 내용 | 시간 | 앱 |
|---|---|---|---|
| 도입 | 강연자 소개: 전파와 통신을 가르치는 ICT폴리텍대학 정보통신학과 | 30초 | 도입 화면에 이름·학과 |
| 원리 | ICT의 뜻: 정보(Information) + 통신(Communication) + 기술(Technology). 폰의 와이파이 막대가 바로 ICT | 1분 | 원리 화면 첫 장 |
| 원리 | 우리나라 전파 이야기 네 장면: 1885 한성전보총국(서울–인천 전신), 1927 경성방송국 첫 라디오, 1996 CDMA 세계 최초 상용화, 2019 5G 세계 최초 상용화 | 1분 30초 | 원리 화면 연표 (FR-02a) |
| 선포 | AI는 전파를 타고 와요: 질문과 답이 전파로 오가고, 전파가 끊기면 AI도 대답할 수 없음. 강연자 폰으로 질문 → 비행기 모드 → 다시 질문 시연 | 1분 | 슬라이드 |
| 선포 | 진로 한 줄: "와이파이와 통신망을 설계하고 운영하는 방법은 정보통신학과에서 배웁니다" | 30초 이내 | 선포 화면 하단 |

- 연표 네 장면은 슬라이드에 넣기 전에 출처를 확인한다.
- 대구 관련 이야기(동구 혁신도시의 한국지능정보사회진흥원, DGIST, 1938년 대구 삼성상회)는 **강연자 참고 메모로만** 둔다. 고정 순서에 넣지 않고, 쓸 때는 사실을 다시 확인한다.

## 5. 시스템 구성

```
[강연용 Windows 노트북 · 단상 왼쪽 연단]
  ├ 모바일 핫스팟 (2.4GHz) ─── 측정 대상 AP이자 통신망
  ├ 수신 서버 (UDP 8601)  ─── 노드 측정값 수신·저장
  └ 강연 앱 화면 (브라우저) ── HDMI → 프로젝터
        ▲
        │ 핫스팟 접속 (동시 접속 최대 8대)
        ├ [탐정 폰] QR로 /p 페이지 → 구역 + 폰 와이파이 막대 수(0~4) 보고, 응답 시간(RTT) 자동 측정 (HTTP)
        └ [측정 노드 ESP32 DevKit] 연결된 AP의 신호세기(dBm)를 1초마다 UDP 전송 (보조·반전 실험용)

[휴대폰 USB 테더링] ─ 핫스팟을 켜기 위한 상위 연결 (검증 필요)

[공개 사이트 wifi-tamjung.vercel.app] ─ 강연과 독립. 정적 사이트
```

### 5.1 설계 결정

| 결정 | 이유 |
|---|---|
| 측정 대상 AP는 강연자 노트북의 모바일 핫스팟 | 도서관 와이파이 허가가 필요 없다. AP 위치를 강연자가 정하므로 거리 감쇠가 분명히 드러난다. 노드는 연결된 AP의 신호세기만 읽으면 된다 |
| AP(노트북)는 연단에 고정, 노드가 움직인다 | 노트북이 AP이므로 노트북을 들고 이동하면 지도의 기준이 흔들린다 |
| 강연 중 인터넷을 쓰지 않는다 | 도서관 망 상태와 무관하게 진행한다. LLM 조교는 넣지 않는다 |
| 참가자 폰을 노드로 쓴다 | 접속한 단말이 보내는 데이터를 모아 지도를 만든다. 아이들이 자기 폰의 막대를 직접 읽어 보내므로 참여감이 크다. 웹은 dBm을 읽을 수 없어 막대 수(자가 보고)와 응답 시간(자동)을 쓴다 |
| 공개 사이트는 강연 앱과 분리한다 | 핫스팟 동시 접속은 8대라 청중 전체가 붙을 수 없다. 공개 사이트는 강연 전후용이다 |
| KIPEE 수신 규격을 이어받는다 | 같은 JSON 형식이면 KIPEE 노드와 도구를 시험용으로 쓸 수 있다. KIPEE 시연 코드 자체는 수정하지 않는다 |

### 5.2 수신 규격

노드는 서버의 UDP 8601로 한 줄 JSON을 보낸다. KIPEE 전파지도의 `Measure` 형식과 호환한다.

```json
{"node_id": "N1", "zone": "L3a", "rssi": -58}
```

- `node_id`: 노드 번호 `N1`~`N4`. 노드 본체 스티커 번호와 같다.
- `zone`: 노드가 모르는 값이므로 노드는 빈 문자열이나 `"--"`를 보내고, **위치는 서버가 붙인다**(FR-04). KIPEE 도구로 시험할 때만 노드가 직접 채운다.
- `rssi`: 정수 dBm. 허용 범위는 −100~−20. KIPEE의 −95 하한보다 낮춘다(호일·물통 실험).
- 서버는 받은 시각을 기록한다. 노드 시계는 쓰지 않는다.

### 5.3 구역 (5곳)

좌석 단위 대신 아이들이 바로 알아듣는 5구역으로 나눈다(2026-09-27 결정). 코드는 2자로 KIPEE `zone` 길이 제한에 맞춘다. 위치는 `app/config.json`에서 바꾼다.

| 코드 | 구역 | 기본 위치(가로, 세로 m) | 비고 |
|---|---|---|---|
| `ST` | 강단 | 5.0, 1.0 | AP(노트북)는 강단 왼쪽 연단 0.9, 0.8 |
| `LW` | 왼쪽 벽 | 0.7, 7.8 | |
| `CT` | 가운데 | 5.0, 7.8 | 통로 |
| `RW` | 오른쪽 벽 | 9.3, 7.8 | 창 쪽 |
| `EX` | 비상구 쪽 | 5.0, 13.3 | 실제 비상구 위치 확인 필요 |

구역마다 폰이나 노드 1~2대를 둔다. 핫스팟 8대 한도 안에서 운영한다.

### 5.4 폰 노드 규격

- 탐정 폰은 핫스팟에 접속한 뒤 `http://<노트북>:8600/p`(대기·측정 화면 QR)를 연다.
- 첫 접속 때 서버가 `P1`, `P2` … 번호를 준다. 서버를 다시 켜면 폰이 번호를 새로 받는다(번호 겹침 방지).
- 아이는 미니 지도에서 **자기 자리를 선택하는다**. 찍은 좌표가 그 폰의 도트 위치가 되고, 가장 가까운 구역이 자동으로 정해진다.
- 폰은 2초마다 `POST /api/phone {id, zone, pos, bars, cell_bars, cell_gen, rtt, mbps}`를 보낸다.
  - `bars` 와이파이 막대 수(0~4), `cell_bars` 휴대폰 데이터 막대 수(0~4): 아이가 폰 상단 표시를 보고 누른 값
  - `cell_gen` 통신 세대(5G, LTE, 3G, 모름): 아이가 폰 상단 글자를 보고 고른 값. 웹은 실제 통신 세대를 알 수 없다(크롬의 연결 정보는 속도 추정값이고, 아이폰 사파리는 제공하지 않음). 6G는 상용 서비스가 없어 선택지에 없다
  - `rtt` 노트북까지 응답 시간(ms, 3회 중앙값), `mbps` 노트북에서 256KB를 내려받은 실제 와이파이 속도: 자동 측정
- 서버는 막대 수를 대표 dBm(0칸 −90, 1칸 −80, 2칸 −70, 3칸 −60, 4칸 −50)으로 바꿔 지도에 쓰고 원래 값도 함께 저장한다.
- **통신 세기와 속도, 지도에 찍은 방 안 좌표만 받는다.** 이름, GPS 위치, 기기 정보, 통신사, 접속 IP는 받거나 저장하지 않는다.

### 5.5 세 가지 신호 비교

| 신호 | 코드 | 누가 재나 | 값 |
|---|---|---|---|
| 우리 공유기(노트북 핫스팟) | `ap` | 측정 노드(dBm), 탐정 폰(와이파이 막대) | 공유기 하나라 거리에 따라 뚜렷이 약해짐 |
| 도서관 와이파이 | `lib` | 측정 노드가 도서관 와이파이 이름을 **접속 없이 스캔**(5초마다) | 공유기가 여러 대라 고르게 잡힐 것으로 예상 |
| 휴대폰 데이터(LTE·5G) | `cell` | 탐정 폰(안테나 막대, 통신 세대) | 5G와 LTE를 나눠 비교 |

선포 화면은 세 신호의 신호가 가장 강한 곳, 가장 약한 곳, 구역 사이 차이(dB)를 표로 보여 준다. 차이가 클수록 자리마다 다르다는 뜻이며, 도서관이 공유기 자리를 설계한 이유(사이트 서베이)로 이어진다.

### 6.1 신호세기 표시 규칙

공개 사이트의 전파 놀이터와 같은 규칙을 쓴다.

| dBm | 막대 | 색 | 아이에게 보이는 말 |
|---|---|---|---|
| −55 초과 | 4칸 | 초록 | 매우 강함 |
| −65 초과 | 3칸 | 연두 | 세다 |
| −75 초과 | 2칸 | 노랑 | 보통 |
| −85 초과 | 1칸 | 주황 | 약하다 |
| −85 이하 | 0칸 | 빨강 | 거의 없다 |
| 3초 무수신 | 없음 | 회색 | 신호 끊김 |

## 8. 기능 요구: 측정 노드 펌웨어 (ESP32 DevKit)

| ID | 우선 | 요구사항 |
|---|---|---|
| FW-01 | P0 | 고정된 핫스팟 이름·암호로 접속. 끊기면 자동 재접속 |
| FW-02 | P0 | 1초마다 연결된 AP의 신호세기(`WiFi.RSSI()`)를 읽어 UDP 8601로 전송. 서버 주소는 접속한 망의 게이트웨이 주소를 쓴다 |
| FW-03 | P0 | 노드 번호는 기기별 상수 한 줄만 다르게. 본체 스티커와 일치 |
| FW-04 | P1 | 보드 LED로 상태 표시: 접속 중 깜빡임, 전송 중 켜짐 (보드별 LED 핀 확인 필요) |
| FW-05 | P1 | 전원을 켜면 버튼 조작 없이 바로 측정 시작 |
| FW-06 | P1 | `LIBRARY_SSID`가 있으면 5초마다 백그라운드 스캔으로 도서관 와이파이 중 신호가 가장 강한 공유기의 세기를 `lib_rssi`로 함께 보낸다. 도서관 와이파이에 접속하지 않는다 |

값이 끊긴 상태(호일 실험)는 노드가 따로 알리지 않는다. 서버가 3초 무수신으로 판단한다.

## 13. 저장소 구조 (제안)

```
wifi-tamjung/
├ docs/        PRD, 운영 점검표, 설계 메모
├ shared/      전파 놀이터 (강연 앱과 공개 사이트가 함께 씀)
├ site/        공개 사이트 (Vercel 배포 루트)
├ app/         강연 앱: 수신 서버(표준 라이브러리만) + 발표 화면 + 탐정 폰 페이지(/p)
├ firmware/    ESP32 노드 스케치
└ tools/       가상 노드(시험용 UDP 송신기), 기증 이미지 생성
```

강연 앱 서버는 Python 표준 라이브러리만으로 만들었다(설치할 패키지 없음). 브라우저만으로는 UDP를 받을 수 없어서 서버가 필요하다. 실행은 `run.ps1`(Windows) 또는 `run.sh`.

## 15. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 인터넷 연결 없이는 Windows 핫스팟이 켜지지 않을 수 있음 | 측정 불가 | USB 테더링 상위 연결. ASAP 검증. 실패 시 휴대용 공유기를 AP로 쓰는 대안 검토 |
| 상위 연결이 5GHz 와이파이면 핫스팟이 같은 대역으로 묶임 | ESP32 접속 불가 | 상위는 USB 테더링만 사용 |
| 한 방 안에서는 신호 차이가 작아 지도가 밋밋함 | 탐정 미션의 재미 저하 | AP를 연단 끝에 두고 가장 먼 자리와 비교, 청중 사이 vs 통로, 반전 실험으로 차이 확보 |
| ESP32 값이 튐 (KIPEE 실측에서 기준 노드도 ±5dB, 순간 20dB) | 칸 색이 깜빡임 | 최근 5개 중앙값(FR-05) |
| 폰 막대 수는 아이가 직접 읽어 누르는 값이라 기종마다 기준이 다름 | 폰 사이 비교가 거칠다 | 구역당 폰 1~2대, 측정 노드 값(dBm)과 함께 보여 줌. 응답 시간은 보조 지표 |
| 인터넷 없는 와이파이에서 안드로이드가 모바일 데이터로 요청을 보낼 수 있음 | 폰 페이지가 안 열림 | USB 테더링으로 핫스팟에 인터넷 제공, 리허설에서 안드로이드·아이폰 각각 시험 |
| 동시 접속 8대 한도 | 폰 참여 인원 제한 | 탐정 대표만 접속, 나머지는 투표·사람 벽(인체 차폐)으로 참여 |
| 노트북 안테나 방향에 따라 값이 달라짐 | 리허설과 본 강연 결과가 다름 | 노트북 위치와 뚜껑 각도 고정 |
| 방 크기·좌석이 추정과 다름 | 격자 불일치 | 템플릿을 설정값으로(FR-01), 도서관 문의 |
| 설치 시간 부족 | 시작 지연 | 대기 화면 점검표, 13:00 도착, B안 |
| 저학년이 dBm을 이해하지 못함 | 몰입 저하 | 막대와 색이 주, 숫자는 보조(6.1) |

## 16. 기획 초안에서 바뀐 전제

| 처음 전제 | 바뀐 내용 |
|---|---|
| KIPEE 서버를 수정 없이 사용 | 수신 규격만 이어받고 강연 앱은 새로 만든다. 캠퍼스용 히트맵(6열 고정)과 노드별 담당 구역은 도서관에 맞지 않는다 |
| 노트북을 4번째 측정 노드로 사용(netsh) | 제외. 노트북이 AP다. netsh는 dBm이 아닌 % 값을 준다 |
| 도서관 와이파이를 쓰고 막히면 폰 핫스팟 | 처음부터 노트북 핫스팟 |
| 호일로 감싸면 값이 떨어진다 | 값을 보내는 통로도 같은 와이파이라 수신이 끊긴다. 끊김을 "신호 끊김"으로 연출 |
| 노트북을 들고 이동하며 지도 변화 | AP는 고정, 노드가 이동 |
| 대상 초등 고학년~중학생 | 실제 청중은 초등 중심, 저학년 포함 |
| 40분 강연 | 본 강연 40분 + 질의응답 8분 + 인계 2분 |
| 좌석 24칸 격자(`L3a`) | 5구역(강단, 양쪽 벽, 가운데, 비상구 쪽) |
| 측정은 ESP32 노드만 | 참가자 폰이 주 노드, ESP32는 보조와 반전 실험용 |
